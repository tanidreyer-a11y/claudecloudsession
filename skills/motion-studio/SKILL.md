# Motion Studio

Built from real client films: brand films a founder approved on first viewing, and a promo a client called
"phenomenal". Rules are ranked by evidence: what got approved beats what sounded good. This skill replaces
`ad-marketing-10k`; all of its content lives here (references/, scripts/, examples/, templates/).

**Read first:** `references/lessons-learned.md` (41 lessons that each cost a rework), then the file for your step.

## Non-negotiables
- **Copy style, never assets.** Never reproduce a reference's logos, footage, music, characters, taglines or exact
  layouts (each card's `do_not_copy`).
- **Licensing:** OFL/free fonts (or the client's licensed font), royalty-free, self-generated or licensed audio,
  and images that are the client's, generated by us/them, or licensed. Every source is listed in the project README.
- **Truth:** no invented statistics, testimonials, client names or results. Products that don't exist yet are never
  shown as live. Unverified claims are flagged.
- **Privacy:** fictional demo data, no real personal data. Say "POPIA-minded" (or "-minded" generally), not
  "compliant", unless it's verified.
- **No house style leaks.** ADC Innovations' and SmartTechNXT's colours, fonts and signature moves are THEIR brand
  profiles, never the default for anyone else. The neutral template and the recipe engine set the look.
- **Quality first.** If a paid add-on is the best option, offer it with its cost and let the client decide
  (production.md §5). Never quietly downgrade.
- **Third-party code:** knowledge only. Vet repos before use (references/third-party-skills.md). Never install hooks
  or MCP configs, never run unknown scripts, and check any script before reusing it.

## 0. First reply — the creative brief (always)
Send `intake.md` in one message, with defaults in brackets. It always asks:
- for the business, the pain and the CTA;
- for brand assets (attach);
- **for images: "Do you have photos or video you'd like to use? Attach them"**, plus how to get any missing images;
- for the feel (vibe axes plus the 9 looks as options);
- for voice and sound, and for formats, deadline, budget and whether paid add-ons are OK.
No code, script or plan before the answers. "Just start" means take the defaults and list them.
Then create or update `brands/<slug>.md` from `brands/_template.md`.

## 1. Working with the client
- Plain language, short sentences, define jargon in one line. They direct; you are the crew.
- **Silence makes people anxious.** Status line every few minutes, honest time estimates, something watchable early:
  recipes → storyboard sheet → draft (even before the voice) → preview with sound → final.
- Respect their wording. When pace is off, reformat before cutting, and cut only with permission.
- Challenge weak ideas with reasons, mark claims [Certain]/[Likely]/[Guessing], give options, let them choose.
- Check the environment early: is the website reachable (`curl`)? Which connectors are attached (imagery.md)?
- Plans change mid-project; switch immediately and keep every version.

## 2. Diagnose an existing video (if they bring one)
Contact sheet at key beats plus frame strips across every transition
(`scripts/teardown.py` or `ffmpeg -ss T -t 1.4 -i in.mp4 -vf "fps=10,scale=384:-1,tile=7x2" -frames:v 1 strip.png`).

| Cheap tell | Fix |
|---|---|
| Text/UI unreadable at the size shown | Effective size (px × zoom) ≥ 24 px when read; fill the frame *when* it's read |
| Fade out → empty background → fade in | Never an empty frame (§7) |
| Same whoosh on every cut | Music carries transitions; UI sounds are notes; ≤ 3 different air moves |
| Decorative blobs and bubbles | Background = light, texture, grid or photo, not objects |
| Flat colour wash, low contrast | Neutral-dominant; colour as light and on one hero element |
| Same pop/fade on everything | Motion inventory: one treatment per content type |
| Camera stop-starts at each key | Monotone spline camera, log zoom, motion blur |
| Long holds, 80+ s, "boring halfway" | 30–60 s, a new beat every 1.5–3 s, holds only on purpose |
| Generic story ("a quiet weight") | Name the concrete pain with real artefacts |
| Shapes pretending to be products/food/people | Real or generated photography (imagery.md) |

## 3. Direction — the recipe engine (never one fixed style)
1. Translate the brief into vibe axes (energy · warmth · density · realism · polish, 1–5), `--ui` (is there a real
   product UI?), `--imagery` (do we have or can we get photos?) and the brand slug.
2. `python3 scripts/recipe.py --axes energy=3,warmth=4,density=3,realism=4,polish=4 --ui no --imagery yes
   --brand <slug> --client "<name>" --json <project>/recipes.json`
3. Present 3 recipes (base card × donor card + one wildcard slot). Give each a logline for THIS business, its
   signature move, fonts, what it needs (photos/UI/paid add-ons) and its risk, plus the comparison table.
   Recommend one; the client picks, mixes or vetoes.
4. Record the pick: `--record <project>/recipes.json --pick N --brand <slug>`.
Details and anti-repetition rules: `recipe-engine.md`. Cards: `library/styles/`. Parts: `library/slots.yaml`.
Shot recipes (Apache-2.0, in Chinese; read them as technique notes): `library/shots/<category>/<name>.md`.

Then write one direction line: *"Reading this as: <piece> for <audience>, <recipe name>, <format>."*

**Story principles (any recipe):**
- **Lead with pain or desire, concrete:** the 21:43 lead, the cold coffee, the empty Saturday class. Then the turn,
  proof, trust and one CTA.
- **Make it a loop**: the stuck thing in act 1 is the one that gets solved; callbacks read as intentional.
- **Logo-anatomy concepts win** when the bible explains the logo; the parts become the cast.
- **One focal point, deeper and deeper**: an object the eye never loses.
- **Specific beats over lists**: one real case beats five features; mention breadth once, late.
- Pitch 2–3 concepts inside the chosen recipe (logline · focal object · signature move · why · risk).
- Chat UI: the brand's agent on the RIGHT in brand bubbles, the customer on the LEFT in neutral.
- Copy gate (default): no em-dashes on screen; avoid elevate, seamless, unleash, empower, leverage, robust,
  game-changer, cutting-edge.
More: `references/story-and-concept.md`, `references/reference-library.md`.

## 4. Imagery (image-led recipes)
If the recipe needs imagery (Cobalt Campaign / NIVO-style photo creatives, Desert Glass places, Cream Cascade
products, craft/food/perfume macros), follow `imagery.md`:
1. the client's own images first;
2. otherwise a connected generator (check what's attached: Adobe Firefly, Canva, Higgsfield, Google Flow…), making
   4+ options per shot and inspecting every one;
3. otherwise a prompt sheet for the user (one prompt per shot, file names, tool, aspect, negative prompt, where it's
   used), building on placeholders meanwhile.
Never fake photographic subjects with shapes.

## 5. Script — feel and pace
Full guide and the approved scripts: `references/script-voice-pacing.md`.
- **Talk → pause to let it sink in → repeat.** One thought per paragraph; pauses live *between* paragraphs.
- "..." only to weight the second half of a line. One-word punches ("Almost."). Rule of three; parallel pairs; callbacks.
- Word budget: ~95–110 words per 60 s calm · 120–140 upbeat · 35–50 for 15–20 s.
- **Hook word** with 1.5–2 s held silence either side (insert it in the edit if the TTS won't hold it).
- **Proven voice:** ElevenLabs Multilingual v2, a deep calm narrator ("Oliver Silk – Deep Gravel Narrative"),
  Speed 0.87, Stability 30, Similarity 80, Style 48. v3/v4 emotion tags tended to whisper: an option, not the default.
  Match the voice to the recipe (a gym ≠ a law firm); offer 2–3 voices.
- Deliver a paste-ready block (blank lines kept) + settings + claims check + estimated length.
- Music-led films without VO: a beat sheet of on-screen words instead (≤ 7 words per card, ≥ 1.2 s each).

## 6. The voice is the master clock
1. Probe every asset (`ffprobe -show_entries format=duration:stream=codec_name,sample_rate,channels`).
2. Word timings with `scripts/align_vo.py` (offline; phonetic, so match by order). Land hits on the **stressed
   syllable** of the meaning word, found from the loudness contour (20–40 ms RMS).
3. **One timeline file** of named keys in seconds, read by both picture and sound; camera keys are relative to words
   (`W.bridge - .5`), so a new take re-times everything.
4. Draft on estimated timings (~1.8 words/s + pauses), re-time to the real take, report which beats moved.
5. A beat too short to read: move the neighbour beat, don't flash the text.
6. Pauses after recording: `scripts/insert_pauses.py` + a smoothstep time-warp so motion eases into the pause.

## 7. Composition, type, colour, transitions
- Title-safe ~54 px (16:9); 9:16 critical content in the middle 75 %. One focal point and one hero colour per frame;
  accent ≤ ~5 % of pixels.
- Fill the frame **when something must be read**; use negative space for brand moments. Effective text size
  (px × zoom) floor 24 px; contrast computed (≥ 4.5:1 body).
- Type scale start: display 128 / title 72–96 / h2 48–56 / body 34 / UI 30 / label 27 / floor 24; negative tracking
  on large type; tabular numerals for counters. Fonts come from the recipe (OFL) or the brand.
- Brand bible wins on palette tokens, fonts, alignment, tagline rules and reverse logo. Never redraw a logo:
  extract it (`scripts/extract_brand_pdf.py`, references/brand-extraction.md).
- Icons are SVG, never emoji. Shadows tinted to the hue. Crossfades between very different fills go through a vivid
  midpoint. A problem act can run cooler; the light lifts at the turn.
- **Never an empty frame.** Transitions come from the recipe (3–4 devices). Overlap outgoing and incoming; exits are
  faster than entrances; never the same device twice in a row. Device notes: references/motion-language.md and
  library/shots/transition/.

## 8. Motion language
- **Camera = monotone cubic spline** through keys (velocity carries through, no overshoot), zoom in log space; move in
  the directions the recipe's camera slot allows. Never chain eased key-to-key moves.
- Element curves: OUT `bezier(0.16,1,0.3,1)` · IN `bezier(0.7,0,0.84,0)` · SWEEP `bezier(0.22,1,0.36,1)`;
  springs pop {13,190,.8} · settle {200,120} · soft {26,80} · snap {18,260,.6}. No linear; clamp; never `scale(0)`.
  The recipe's motion_feel slot picks which ones dominate.
- Entrances animate 2–3 properties; stagger 3–6 frames; things on screen > 2 s breathe; stills get Ken Burns.
- **Print the motion inventory** (content type → treatment) before delivery; a repeat is a bug.
- Full rules: `production.md` §2, `references/motion-language.md`.

## 9. Sound (half of perceived quality)
- Music bed first (the recipe's sound slot). Chord changes on story beats: tense in the problem, open at the turn,
  bloom at the logo, resolve.
- UI sounds are notes in the current chord, with varied pitch and pan; sequences ascend.
- Foley only with meaning; **≤ 3 whoosh/air moves per film**, each different.
- Silence is a sound: drop the music for the hook word.
- Duck music −9 dB / SFX −4.5 dB under the voice. Hits 0–3 frames early. Pan to the source.
- Master to **−16 LUFS, true peak −1.5 dBTP** (−14 for short-form if agreed) with `scripts/finish.sh`; verify.
- You can't hear the result, so say so, keep synthesis conservative, and offer a licensed track as a paid add-on
  when the recipe needs real instruments (acoustic, orchestral).
- Details: `references/sound-design.md`; kit: `scripts/sound_design.py` (re-cue its example to these rules).

## 10. Build
`production.md`: theme first, the 14 motion rules, build order, formats, paid add-ons.

| | HTML engine (cloud / any machine) | Remotion (laptop, live preview) |
|---|---|---|
| Start | `scripts/engine/film_template.html/js` + `examples/` | `templates/remotion/` (neutral theme-driven components) |
| Timeline | `timing.js` (`W`, `DUR`) | `src/timeline.ts` |
| Motion | pure `render(t)`, spline camera, DOM/SVG | `useCurrentFrame()`, interpolate/spring, `useCamera` |
| Render | Playwright → ffmpeg; 60 fps + `tmix` → 30 fps blur | `--gl=angle`, chunked resumable renders |

Both: stills contact sheet before every full render, and actually look at it.

## 11. Finish, QA, deliver
`scripts/finish.sh master.mp4 out/name [MB]`: BT.709-tagged grade, subtle grain, loudness, CRF 18 master, two-pass
web file under budget, verification. Then run **`qa-checklist.md` on the encoded file** and paste it into the delivery.
Deliver one final mix (voice + SFX + music) unless asked otherwise, plus a share copy (< 30 MB chat, < 15 MB WhatsApp).
Commit and push everything to the user's repo (videos included) unless they say otherwise.

## 12. Workflow
1. Brief (§0) → wait → lessons-learned → probe assets, check network and connectors.
2. Brand profile (+ extraction) · diagnose an old cut · tear down any new references (maintenance: add-reference).
3. Recipe engine → 3 recipes → client picks → record.
4. Script/beat sheet + voice settings → client records. Meanwhile: imagery plan, storyboard sheet, draft → send.
5. Align → re-time → stills audit → audio (LUFS) → preview with sound → send.
6. Full render → finish → QA checklist → deliver → commit + push.
7. Final message: files + sizes, recipe, deviations, motion inventory, claims to confirm, image sources.
8. Log feedback (maintenance: feedback). Quote if asked (`references/pricing-and-delivery.md`).

## 13. Definition of done
- Duration = voice/beat sheet; every animation on its word or syllable (±0.1 s).
- Recipe followed and recorded; not a repeat of the last project or this brand's last film.
- No empty frames, no stop-start camera, no repeated transition sound or treatment.
- Zero text errors in a 20-frame audit of the encoded file; readable on a phone.
- Loudness target met; web file under its limit; master saved.
- Brand followed; logo extracted; claims verified or flagged; all sources listed.
- Client saw recipes, a storyboard/draft and a preview before the final.
